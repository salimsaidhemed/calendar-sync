# Calendar Sync v0.1.0

First one-way Google Calendar → Nextcloud worker baseline. This file describes source version 0.1.0; publication is established by the owner-approved Git tag/GitHub release, not by the file's existence. The release PR must merge before tagging under issue #14.

## Included

- One explicit Google source calendar and one Nextcloud CalDAV calendar per worker configuration; personal Google/Workspace authorization guides, default Nextcloud origin https://nextcloud.tcadc.com.
- Ordinary timed/all-day event create/update with dry-run default, deterministic identities, ownership/content verification, conditional PUT and confirmed readback.
- SQLite schema 2 mappings, run/audit history, durable pending intents and crash reconciliation; quiesced verified backup/isolated restore helper.
- Continuous polling, retry/cooldown, SIGTERM/SIGINT shutdown, lifetime state lock and private last-cycle health.
- Unprivileged read-only Docker/Compose operation, dedicated secret references, local Docker UAT and customer Workspace production guides.
- `calendar-sync --version`, pinned runtime dependency versions and a runtime-lock verification command. Bare `calendar-sync` remains an offline configuration check; `calendar-sync worker` starts provider operations explicitly.

## Explicit exclusions and operating limits

No GUI/FastAPI/Keycloak, multi-user scheduler, Google writes, Chat, recurrence expansion, bidirectional edits, deletes, invitations, auto-adoption or automatic conflict winner. Recurring masters/instances/exceptions and cancellation records are skipped. Missing/cancelled sources retain destination copies/mappings. Destination edits conflict; restoring the title does not restore the saved ETag.

Attendees, organizer, conferencing, attachments, reminders and privacy/availability fields are not reproduced. Choose destination permissions appropriately. Lost/older state does not authorize reconstruction/adoption; restoring SQLite does not undo remote writes. Preserve the same configuration/calendar identities and state volume.

Use one cooperating process/replica per local POSIX SQLite database; Linux containers/macOS are tested, Windows/network/shared filesystems unsupported. The Google token parent must be writable/private for refresh; tokens can be revoked/expire and customer administrator policy still applies. No automatic audit/intent purge or retention migration exists. Health is last-cycle/mode-aware, not proof every event/field synchronized or independent process liveness; Docker unhealthy alone does not restart a running process. No throughput or production hard-stop deadline is promised.

## Dependencies and artifact identity

[requirements.lock](../../requirements.lock) records 19 runtime versions validated for Python 3.12 Linux. CI and Docker install these pins, then install the package without resolving new runtime versions; `python scripts/check_runtime_lock.py` checks installed metadata/pins. The image exposes OCI version/revision labels when built with VCS_REF.

The Python base tag, OS/build dependencies and wheel hashes are **not fully pinned**. A valid multi-platform base manifest digest was not established during this preparation, so no unverified digest is committed. Version pins are not a claim of bit-for-bit reproducible builds or a security-vulnerability audit. Record the final source SHA, image ID/published digest, architecture and installed versions; retain the approved built image rather than assuming future rebuilds are identical. No registry image or package upload is performed by this release PR.

## Acceptance evidence

Automated safety cases cover duplicate prevention, no-delete, pagination/partial reads, outages, cancellation/recurrence skips, all-day/DST, configuration isolation, token redaction, write races/ambiguous responses, restart recovery and snapshot/restore. All cases are individually documented in [the catalogue](../test-cases.md); release packaging cases validate version/default-offline behavior and dependency-lock failures.

[Owner-reported worker UAT](../worker-uat-evidence.md) includes native and Docker create/repeat/restart/health/clean-exit results. Exact original dirty-tree SHA/account class, visual duplicate/date/type/conflict-title checks and final dry-run cleanup confirmations were not supplied. They remain qualified, not silently passed. Real customer production authorization/deployment/backup/restore and all account-class interoperability have not been executed by the author. Record actual customer results separately; a source release is not customer go-live approval.
